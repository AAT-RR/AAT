AAT Pro User Guide

Load or record a WAV, pick a channel, and every meter, chart, and analysis tool in this window reads from that one signal. This guide walks the menu bar left to right — File to Help — the same order the toolbar reads.

No audio loaded yet? Start at Core Workflow

Core Workflow start here

Everything below the menu bar exists to get a signal in, look at it, and hand it to a tool. Every analysis in Tools reads from whatever is loaded here.

Load WAV / Record→ pick a channel→ read the charts→ run a Tools/Design feature→ save WAV / image / CSV

Getting a signal in

1Load WAV... / Record

Load WAV... opens a file picker for an existing .wav. Record captures fresh audio from the device chosen in Input device:, for the duration set in Settings... (default 3.0s, range 0.5–30s). Check Record 2 Mics and pick a 2nd Device: to capture two devices at once into one multi-channel buffer.

Every recording is auto-saved to recordings\rec_YYYYMMDD_HHMMSS_NNN.wav next to the executable the moment it finishes (the log panel shows the exact path) — on top of showing up in Loaded Files for immediate analysis. File > Save WAV... is still there for saving a copy somewhere else.

Check Mic Input runs a one-shot input-level check on the selected device — useful for confirming a mic is actually picking up sound before committing to a full recording.

Working with the loaded signal

2Loaded Files (left dock)

Every file you load or recording you make is added here as a per-channel checklist — a multi-channel file expands into one checkable row per channel; a mono file is a single checkable leaf. Checking a channel doesn't just select it for preview: it also feeds Spectrogram's and Plot FFT's Plot All mode, so you can check channels from several files at once and analyze that exact combination.

Clicking directly on a channel row (not just checking its box) also switches the main Channel: combo to preview that channel immediately. Add File(s)..., Remove, and Clear List manage the list.

Remove behaves differently depending on what row is selected: removing a whole file's row deletes it from the list entirely, but removing a single channel row instead unchecks and hides just that channel — its audio isn't deleted, later analyses (and Play, see below) simply skip it. Use this to exclude one bad channel from a multi-channel file without discarding the whole recording.

Select Time Range... — the button under the file list analyses only part of the active file, for example to skip the first second (a start-up click, the moment you pressed record) or to drop the tail. Click it to open a dialog showing the whole waveform:

  • Drag the two red lines on the waveform, or type exact values into Start and End (seconds, to the millisecond). The two stay in sync, and the part outside the range is greyed out. End equal to the file duration means “to the end”.
  • Use Full File resets the range to the whole file. Click OK to apply, or Cancel to leave things as they were. A range with zero length is not accepted.
  • When more than one file is loaded, Apply this range to all loaded files sets the same range on every file — handy for comparing files over the same time slice. If the range falls outside one of the files (for example the start is after the end of a shorter file), the range is not applied to any file — every file keeps its previous range — and a message appears in the status bar.

The range belongs to each file separately and the original audio is never modified or discarded: you can reopen the dialog at any time to move it or click Use Full File to get everything back. The active file's label shows the range, e.g. File: test.wav [range 1.000 - 8.500 s], and the audio-info line below the waveform shows the shortened length. The range lasts for the session (it is not saved in settings.ini and not remembered after you remove the file or restart), and files you load, record or generate afterwards start with the full length.

Gain... — the button next to Select Time Range... raises or lowers the level of the active file, for when a recording is too quiet to see or hear properly. Type a value in dB (positive = louder, negative = quieter) or use the quick buttons (−6, +6, +12, +20, +40 dB, each added to the current value). Normalize peak to -1 dBFS picks the gain that brings the loudest sample (within the selected time range, if one is set) to −1 dBFS, and Reset (0 dB) removes the gain. The dialog shows the file's peak before and after the gain so you can see how much room there is. With more than one file loaded, Apply this gain to all loaded files sets the same gain on every file.

  • Only the data in the program is changed. The original .wav on disk is never touched, and the gain is forgotten when you close the program (it is not saved in settings.ini); reload the file and you get the original level. The gain only reaches a file if you save it yourself with File > Save WAV... or Edit > Save Data to CSV, which then contain the amplified data.
  • It works together with the time range. You can set both; the range is cut first and the gain applied to what is left. Each can be changed or cleared at any time without affecting the other. The active file's label shows both, e.g. File: test.wav [range 1.000 - 8.500 s] [gain +12.0 dB].
  • It applies to the same features as the time range (see the table below): the charts, Play, every analysis and processing tool, and Export Report all see the amplified signal. Level readings in dBFS therefore go up by the gain you set.
  • No clipping in analysis. Samples that exceed full scale after the gain are kept as they are, so analysis results are not distorted. Play cannot output more than full scale, so playback is clipped there (a message appears in the log); lower the gain if it sounds distorted.
  • Waveform Statistics keeps dB SPL true. Its dB SPL, dBA, Max RMS dBA and Peak dBA rows subtract the gain you added, so they still show the real sound level at the microphone, while the dBFS rows (Peak Amplitude, Min/Max/Avg/Total RMS Power) show the amplified signal. The line at the top of that window says so whenever a gain is in effect. Other tools that report absolute levels do not compensate — the gain is part of the signal they see.

What the range applies to. It is applied once, to the file itself, so everything that reads that file's audio sees only the selected part — there is no per-tool setting to remember:

One exception — the 3D Waterfall window. If you change a range or a gain while it is open, it keeps showing the old data: close the window and open it again from Tools to pick up the change. Results already on screen in other windows (for example a Plot FFT you left open) are likewise not redrawn; rerun the tool to apply the change.

3Channel: combo + Settings...

Selects which channel of the active file the charts, meters, and single-file analyses read. Settings... opens the shared analysis parameters every Tools feature reads from: Duration (or check Use Loaded File Duration to match the file itself), Sample Rate (44100 / 48000 / 96000 Hz), FFT Size (256–65536), Window (Hann/Hamming/Blackman/Flattop), and Overlap % (0–95).

4Spectrum & Waveform charts

Two stacked, resizable charts — frequency spectrum on top, linear-time waveform below — with Fit to Data (reset zoom) and Pop Out (undock into its own window) on each. Every analysis result and status message is recorded in the log, which opens from Edit > View Log....

Log frequency axis — the checkbox above the spectrum switches its frequency axis between logarithmic (the default, ticked) and linear. Logarithmic spreads the low frequencies out and suits most audio work; linear is easier to read for evenly spaced harmonics or high-frequency detail. Switching resets the spectrum's zoom. The choice lasts for the session only and is not saved in settings.ini; the Plot FFT... window has its own independent checkbox.

Many channels at once. With All Channels selected, every channel is drawn on the same charts, and drawing tens of thousands of points per line gets slow as the channel count grows. To keep the window responsive the waveform chart shares a fixed number of points among the channels: 1–2 channels get the full 25,000 points each, more channels split a total of 64,000 (for example 8,000 each for 8 channels, 4,000 each for 16, never fewer than 2,000). The waveform is thinned by taking evenly spaced samples, so with many channels a very short click can fall between two drawn points and not show on the chart — this affects only the drawing; the analyses in Tools always use the full data. From 8 channels upward, antialiasing (line smoothing) is also turned off on both charts — with that many overlapping lines the difference is not visible, but redrawing is noticeably faster; as a side effect File > Save Plot to Image... then exports unsmoothed lines. The spectrum keeps all its points so narrow peaks are never lost.

5Default Devices

Two sliders controlling the real Windows default playback and recording device volume (via Core Audio) — not this app's own signal gain, and not the Mic level: meter, which is a read-only display. Check Apply to All Playback/Recording Devices to push a slider's value to every active device of that type at once, not just the current default.

6Realtime Spectrum

Opens a live-updating FFT view of the microphone currently selected in Input device: — independent of Loaded Files, for monitoring/measuring a mic directly rather than analyzing a recording. Streaming starts the moment the window opens. FFT Size (1024–8192) and Log Freq control the spectrum's resolution and frequency axis; Weighting (Z/A) applies the A-weighting curve to the displayed spectrum and its peak list, not just the meter below. The top 3 peaks are marked on the chart itself and listed underneath with their exact frequency and level.

A large dBA readout acts like a hand-held sound level meter — smoothed with a selectable Time Weighting (Fast 125ms / Slow 1s, the same IEC 61672 pair a real SPL meter offers; this also smooths the spectrum chart itself, not just the number). To calibrate it against a reference acoustic calibrator: set Reference SPL to the calibrator's printed level (typically 94 dB), hold the calibrator on the microphone, and click Calibrate... — it averages the level for a few seconds and solves Mic Sensitivity so the reading matches that reference. Calibration is saved per microphone (by device name, in settings.ini's [MIC_CALIBRATION] section) and reloaded automatically the next time this is opened against that same mic.

Input overflows should stay at 0. If it keeps climbing while a steady input is playing, the spectrum/level readings will look unstable — a peak flickering or fading even though the input itself isn't changing — because the audio capture is dropping data, not because of anything wrong with the input signal. A separately steady tone that visibly decays over a few seconds with the overflow count still at 0 instead points to the microphone's own driver/OS-level automatic gain control or noise suppression (check its “Enhancements” settings), or the hardware itself.

7Play

Plays back the channel currently selected in Channel:. With All Channels selected, it mean-downmixes whichever channels are checked in Loaded Files (or just the first channel if none are checked) into one mono stream, rather than trying to open one output channel per loaded channel — which fails outright once the file has more channels than the output device supports. Check Loop to have playback restart from the beginning automatically each time it finishes, instead of stopping (unchecking it takes effect at the next natural end, not mid-playback).

A red playhead line on the Waveform chart tracks position during playback. Click and drag directly on that line to scrub — while playing, dragging seeks live; while stopped, dragging just moves the marker, and the next Play starts from there. Dragging anywhere else on the chart still does the usual zoom (drag = rubber-band zoom, right-button drag = move the view, right-click = reset zoom), unaffected.

No default device found? The panel greys itself out and shows “N/A” — this happens on a machine with no active playback or recording device and doesn't affect anything else in the app.

The live file is %APPDATA%\AAT\settings.ini on Windows (macOS: ~/Library/Application Support/AAT/settings.ini; Linux: ~/.config/AAT/settings.ini), created automatically the first time anything needs it — there's normally no reason to create or locate it by hand. It's a separate file from the Python build's aat.ini, kept under its own name specifically so the two builds never read or overwrite each other's configuration.

If that file doesn't exist yet and a settings.ini is found next to the running executable, its [SETTINGS]/[FFT_LIMITS]/[DOA_ANALYSIS] content is copied in as the starting point for that machine's very first launch — this is how a fresh install can ship with pre-configured FFT limit curves or a DOA layout already in place, instead of starting blank. [LICENSE] is deliberately never part of that template: it always gets generated fresh, per machine, the first time the app actually runs there.

Unit Converter...

A standalone calculator for the conversions that come up in acoustic and audio work. Pick a Category and type a value; the result updates as you type. Categories: Length / Distance, Temperature, Pressure and Frequency unit conversions; dB ↔ Linear Ratio (choose amplitude 20·log10 or power 10·log10); Distance Attenuation (dB change between two distances, and the SPL at the second distance); Speed of Sound & Wavelength (speed from air temperature, wavelength ↔ frequency); Mic Spacing ↔ Aliasing Frequency (highest alias-free frequency for a mic spacing, and the reverse); Multi-Source dB Sum (total level of several sources); A-Weighting Correction; Audio Electrical Levels (dBu / dBV / dBm); and RMS / Peak / Peak-to-Peak Voltage.

DOA Analysis (Pairwise)

Prompts a mic layout type (circular/linear — remembers your last choice) and distances-from-reference in meters, comma-separated (remembers your last input, even if it later turns out invalid, so you can just fix it rather than retype it). The channel currently selected in the main Channel: combo is the reference mic.

Computes each channel's arrival angle relative to the reference via cross-correlation, logs every pair, then opens a visualization: mic positions, one ray per pair's angle, the averaged direction as a solid arrow, a 0° reference line, and the resulting angle as an arc — with a Save Image... button. The angle diagram is a stylised flat-plane projection (a subtle skew, not real 3D) since the geometry itself is inherently flat.

Scan Test

What it checks: which test stimulus a recording contains and what its parameters are. Scan Test tracks the dominant frequency over time, classifies the stimulus (stepped sweep, continuous sweep, pure tone) and then reports its parameters: sweep type, sweep direction, frequency range, step size (resolution), dwell time, and the wake/sync tone in front of it. Use it to confirm that a device played the stimulus your protocol calls for before trusting any other measurement on that recording. With an expected stimulus entered (or loaded from a file), every channel is checked against it and gets a PASS/FAIL per parameter.

The settings window: opening Tools > Scan Test shows one window with two parts. Everything on it is remembered for next time.

  • Detection settings (left) control how the frequency track is cut into steps. A new step starts when the frequency changes by more than Jump Threshold. A step only counts if it is stable (Variance Threshold) for at least Minimum Step Duration. Neighbouring steps closer than Frequency Tolerance are merged. At least Minimum Distinct Steps are needed to call it a stepped sweep. Enable Pilot Detection looks for the wake/sync tone in the first Max Pilot Search Duration seconds: a tone that stays stable (Pilot Variance Threshold) for at least Minimum Pilot Duration.
  • Stimulus parameters (right). With Auto-detect ticked (the default), Scan Test only reports the parameters it finds. Untick it to enter the expected stimulus: sweep type (stepped, continuous log, continuous linear, pure tone), direction, start frequency, step spacing (1/N octave, Hz per step, or irregular to check only the number of steps), resolution, number of steps, dwell time per step, sweep duration (continuous sweeps), and the wake/sync tone (frequency and duration). Fields that do not apply to the chosen type are greyed out. For stepped sweeps the end frequency follows from start, spacing and number of steps. Every channel is then checked against these values when the results open.
  • Tolerance (used for the check): frequencies in %, resolution / sweep rate in %, and durations (dwell, sweep, wake tone) in %. Sweep type, direction, wake tone present/absent, number of steps and step spacing must match exactly.
  • Save... writes the whole window (detection settings, Auto-detect, expected stimulus, tolerances) to a JSON file. Use it to keep one setup per product or test line. Load... reads such a file back. It also accepts a parameter file saved from a result window (see below): that fills in the expected stimulus and unticks Auto-detect, so a known-good unit can become the reference in two clicks.

Reading the result: the line at the top summarises the stimulus (type, direction, wake tone). The chart plots the tracked frequency over time, with a dashed line where the wake tone ends and dotted lines at each step it found. Below it, the detected parameters. The example is an R40 stepped sweep from 20 kHz down to 100 Hz with a 1 kHz wake tone: 93 steps of 1/40 decade, each held for 30 ms at the top and up to 0.73 s at the bottom.

ParameterHow it is found
Sweep typeStepped, Pure tone, Continuous (log) or Continuous (linear). For continuous sweeps the tracked frequency after the wake tone is fitted both as a straight line in Hz and as a straight line in octaves; whichever fits better decides log or linear. Unknown means the stimulus could not be classified (the original classification text is shown as a tooltip).

How the parameters are measured. The parameter table uses a separate high-resolution analysis, so it also works for stimuli with very short steps, small steps and frequency-dependent dwell times (R40 sweeps and similar). It estimates the tone frequency every 5 ms from a short window (switching to a longer one at low frequencies, so a step of a few Hz is still resolved, to about 0.1 %). A new step starts wherever the frequency moves by more than 1.5 %; anything shorter than the analysis window is treated as the transition between two steps. Silence before and after the stimulus is ignored. Whether the frequency stays flat within each piece decides stepped or continuous. A first steady tone counts as the wake/sync tone only when it does not fit the rest of the stimulus (a different direction, or a much bigger jump than the steps), so a stimulus without a wake tone is not misread; this works whether or not Enable Pilot Detection is ticked (that setting only affects the chart's own analysis). The detection settings on the left (Jump Threshold etc.) drive the frequency-tracking chart and the step markers. If the high-resolution analysis cannot make sense of a recording, the table falls back to the chart's own result. The chart's tracking is coarser (about 23 Hz, 43 ms frames), so for R40-type stimuli its curve looks smooth even though the table correctly reports steps.

Saving parameters and checking against a reference:

  • Save Parameters... saves the detected parameters of the selected channel (the selected table row when several channels are shown) as a JSON file. Use it to record what a known-good unit played, as a reference for later checks, or to re-create the stimulus in Generate Signal....
  • Compare with Reference... loads a parameter file and checks every channel in the window against it, using the tolerances stored in the file (3 % / 10 % / 10 % if none). The same check runs automatically when Auto-detect is off in the settings window. A Reference column shows PASS/FAIL per channel (hover a FAIL to see which parameters are out of tolerance), the line next to the buttons summarises the result, and a detail window lists every parameter with its reference and detected value:

Checking several channels or files: check the channels you want in Loaded Files (any combination, from one or several files) before opening Tools > Scan Test. Every checked channel is analysed with the same settings, in parallel on all CPU cores, each at its own file's sample rate. The result window then shows a comparison table with one row per channel: sweep type, direction, frequency range, resolution, dwell time, wake tone and (after a check) the reference result. Click a row to jump to that channel's chart. Below the table is one frequency-tracking chart per channel, each followed by its parameters. Overlay all channels draws every channel's tracked frequency on one chart in its own colour, so units that played a different stimulus or drifted stand out at once. A channel that cannot be analysed (for example a recording that is too short) shows its error in its row without affecting the others. Fit to Data resets every chart. With nothing checked, Scan Test analyses the channel selected in the Channel: box; Export Report follows the same rule (and fills in the Reference column when Auto-detect is off).

Steps: load the recording(s); select the channel to check, or check several channels to compare them. Open Tools > Scan Test. Stimulus Response Test...

What it checks: how each unit actually responded to a known stimulus, step by step. Scan Test tells you which stimulus a recording contains; this tool takes that stimulus as given, finds every step of it in each recording and measures it: level per step (the frequency response), THD per step, rub & buzz per step, the measured frequency and dwell of each step, dropouts inside a step and missing steps. Each unit is then compared with a golden unit (a known-good recording) and gets PASS/FAIL with the failing steps named. This first version handles stepped stimuli and pure tones; continuous sweeps are not supported yet.

The workflow:

  1. Get the stimulus file. Open the stimulus (or a good recording of it) in Tools > Scan Test and click Save Parameters.... The JSON file holds every step's frequency and dwell plus the wake/sync tone. If you only have the parameters, enter them in the Scan Test settings, or regenerate the WAV with Generate Signal (“Scan stimulus (from Scan Test JSON)”) to play it to the units.
  2. Create the golden. There are three ways, use whichever is easiest:
    • From a golden WAV (simplest). Open Tools > Stimulus Response Test..., click Load... and pick the WAV recording of a known-good unit. The stimulus is detected automatically from the recording (the same high-resolution detection as Scan Test: steps, frequencies, dwell times and wake tone), then the recording is measured against it and becomes the golden. No stimulus JSON is needed. For a multi-channel WAV you choose one channel, or all channels averaged. A message shows the detected stimulus and how many steps were found; click Save Golden... to keep the result as a golden JSON file.
    • From checked channels. Load the recording(s) of one or more good units, check their channels in Loaded Files and click Create Golden from Checked Channels. The checked units are measured and averaged into the golden. If no stimulus is loaded, it is detected automatically from the first checked channel. You are asked where to save the golden JSON.
    • From a golden JSON saved earlier (here or on another PC): Load... and pick it.
    The golden is also remembered for the next run.
  3. Test the units. Load the recordings to test, check their channels (or select one channel), open the tool again and click Run Test. All checked channels are measured in parallel on every CPU core.

The setup window: Load... accepts a golden WAV, a golden JSON saved here, a stimulus file from Scan Test, or a Scan Test settings file; the box shows what is loaded, the detected or loaded stimulus, and whether a golden is available. Save Golden... writes the golden (stimulus, per-step golden values and the tolerances) as JSON; Save Stimulus... writes only the stimulus parameters in the Scan Test format, so Generate Signal can re-create the stimulus WAV from them. Without a golden, Run Test only measures and shows the values, with no PASS/FAIL. The tolerances are stored in the golden file and can be changed before every run:

  • Level per step — allowed deviation from the golden level at each step (default ±3 dB).
  • THD per step / Rub & buzz per step — allowed increase over the golden value (default +5 % / +2 %).
  • Frequency vs stimulus — how far the measured step frequency may be from the stimulus (default ±3 %).
  • Dwell vs stimulus — how far the measured step length may be from the stimulus (default ±20 %).
  • Step counts as missing at — a step whose level is this far below the golden (default 20 dB), or that cannot be found at all, is reported as missing.

How it measures: each recording is first analysed with the same high-resolution step detection as Scan Test, and its steps are matched in order to the stimulus steps (a step that is absent is reported missing rather than shifting all following steps). The recording may start at any time; the offset is found automatically. Every step is measured over its middle 70 %, away from the transitions: level in dBFS, THD from the harmonics, rub & buzz as the energy of the high-order harmonics, and the measured frequency. A short drop in level inside a step that recovers within the same step is reported as a dropout.

Reading the result:

  • The line at the top says how many units failed. The table has one row per unit: PASS/FAIL, number of failed steps, worst level deviation from the golden, maximum THD and R&B, and the problems with the first failing steps named (for example 2540 Hz: level +4.1 dB). Click a row to see that unit's steps below.
  • The charts have one tab each for level (the frequency response), THD and rub & buzz, plotted against step frequency. Every unit is a coloured line; the golden is the light line and the tolerance limits are dashed. Steps that fail are marked with a red dot, so you can see at a glance where a unit goes wrong. Hover to read values, drag to zoom, right-drag to move, right-click to reset.
  • The step table at the bottom lists every step of the selected unit: stimulus frequency, measured frequency and deviation, level and its deviation from the golden, THD, R&B, dwell (with the stimulus dwell), the step's result and its problems.
  • Save CSV... writes every step of every unit with the measured values, the golden values and the results, for your own reports or statistics.

Typical problems and how they show up: a weak or damaged driver shows level below the golden over a band; a resonance or loose part shows a level bump or R&B at a few steps; a distorting amplifier or overdriven speaker shows THD rising, usually at low frequencies; an intermittent connection shows a dropout or missing steps; a unit that played the wrong stimulus shows frequency or dwell errors on most steps.

Chamber Response

What it checks: how the acoustic level at a handful of specific frequencies of interest behaves over the duration of the recording — e.g. confirming a chamber's target test tones stay present and stable for the whole measurement, spotting a dropout, drift, or an unexpected spike partway through. It does not summarize the whole file into one number; it plots one full level-vs-time curve per requested frequency so you can see exactly when and how each one changes.

How it's computed: the signal is turned into a spectrogram (a short-time Fourier transform), then for each frequency you list, the bin nearest that frequency is tracked frame-by-frame and converted to dB relative to the loudest point anywhere in the whole recording — so 0 dB always means “the loudest moment in this file,” not an absolute level. Optional A-Weighting/Gain are applied before that; optional Rolling Average smooths each curve afterward.

Reading the result: one curve per target frequency, overlaid, labeled by frequency in the legend. There's no built-in pass/fail line — you compare the curves against your own acceptance criteria (e.g. “every target tone should stay within N dB of its starting level for the whole recording,” or “no target tone should ever drop more than N dB below the loudest moment”). Watch for a curve that dips, cuts out, or spikes relative to the others.

Steps: load the recording, select the channel, open Tools > Chamber Response, edit the target frequency list (comma-separated Hz, default 200/500/1000/3000/7000/10000) and the A-weighting/gain/rolling-average options, click OK, then read the level-vs-time curves.

loaded file, specific channel
Chamber Isolation

What it checks: how many dB of sound isolation exists between two different moments in the same recording, across a range of frequencies — the classic use case is a “before/after” measurement: mark a window while a chamber door/lid is open (or a seal untreated) and a second window after it's closed (or treated), and this tells you, frequency by frequency, how much quieter the second window is than the first.

How it's computed: for each frequency in your scanned range (Start/End/Step Hz), the level inside Time Window 1 is averaged, the level inside Time Window 2 is averaged separately, and isolation at that frequency is simply the absolute difference between the two averages, in dB. A larger number means a bigger level difference between the two windows at that frequency — i.e. more isolation.

Reading the result: an Isolation (dB) vs. Frequency (Hz) curve, one point per scanned frequency. There's no automatic pass/fail — compare the curve against your own isolation spec (e.g. “need at least 20 dB of isolation across 500–5000 Hz”) and look for any frequency band where isolation is lower than expected.

Steps: load the recording, select the channel, open Tools > Chamber Isolation, set the two time windows (start/end seconds each) to bracket the “before” and “after” moments you want to compare, set the frequency sweep range and step, click OK, then read the isolation-vs-frequency curve.

Tonal Noise

What it checks: whether an unwanted, persistent single-frequency (“tonal”) noise — a motor whine, a switching-supply whistle, a fan tone, etc. — shows up and lingers over time in the recording. This always tracks and plots the signal's dominant frequency frame-by-frame; two further, optional layers add real detection on top of that: Abnormal Noise Detection flags any tone within a frequency band you specify that stays above a dB threshold for at least a minimum duration, and Cumulative Noise Analysis takes the single worst (longest) such event and checks it against a maximum-allowed duration — this last check is the one place this tool gives you an explicit PASS/FAIL.

How it's computed: a spectrogram tracks the dominant frequency every frame (smoothed for the main curve). When abnormal detection is on, each frame is also searched for a noise peak inside your Freq Range that clears both a prominence and width threshold and stays within Freq Tolerance of the previous frame's peak (so a real persistent tone can be told apart from one that just happens to be loud for an instant); a peak track is only promoted to a reported “abnormal noise event” once it holds for at least Min Abnormal Duration. If cumulative analysis is also on, the single longest such event's duration is compared against Max Cumulative Duration.

Reading the result: the chart always shows the dominant-frequency curve; with abnormal detection on, it adds a shaded band showing the searched frequency range and shaded regions marking each detected event. Below the chart, one line tells you the actual verdict: “Cumulative noise analysis: disabled” if that check is off, “...no qualifying noise detected” if it's on but nothing crossed the threshold long enough, or “X Hz, Y s (PASS)” / “(FAIL)” stating the worst event's frequency and duration and whether it stayed under your allowed maximum.

Comparing several channels or files: check the channels you want in Loaded Files (any combination, from one or several files) before opening Tools > Tonal Noise. Every checked channel is analysed with the same settings, in parallel on all CPU cores, each at its own file's sample rate. The result window then shows:

  • a comparison table at the top, one row per channel: the number of abnormal noise events, the longest event (duration and frequency), the most cumulative noise (frequency and total time) and its PASS/FAIL result. Click a row to jump to that channel's chart. A channel that cannot be analysed (for example a recording that is too short) shows its error in its row; the other channels are not affected.
  • below it, one chart per channel, the same chart as for a single channel, each followed by its event count and cumulative result.
  • Overlay all channels — replaces the per-channel charts with one chart: each channel's dominant frequency is a solid line in its own colour, its tracked noise peak a dashed line in the same colour, and each abnormal noise event a thick segment in that colour, drawn at the event's frequency from its start to its end. This shows at a glance which unit has a tone, at what frequency and when.

Hover over a line to read time and frequency; drag a box to zoom, use the mouse wheel, hold the right button to move the view, and Fit to Data (or right-click) to return to the full view. With nothing checked, Tonal Noise analyses the channel selected in the Channel: box exactly as before. Export Report follows the same rule and puts all checked channels on its Tonal Noise page.

Steps: load the recording(s), select the channel (or check several channels to compare them), open Tools > Tonal Noise, set the frequency range and dB threshold, tune peak-detection sensitivity if needed, check Abnormal Noise Detection and/or Cumulative Noise Analysis if you want the event/duration checks (leave both unchecked for a plain frequency-tracking view), click OK, then read the chart and the verdict line underneath it.

Tonal Teams...

What it checks: per channel, whether the recording's overall frequency spectrum has a narrow tonal spike — a whine, hum, whistle, coil noise or resonance — that stands out abnormally against the channel's own general spectral shape. Nothing is compared against an external reference curve or spec: the channel is its own reference, so the test works on any recording without a golden sample. Each channel is judged independently and comes back PASS or FAIL, which makes this the closest thing in this app to a production-line pass/fail test.

Tonal Teams vs. Tonal Noise: two separate tools, deliberately not merged, because they answer different questions. Tonal Noise follows the dominant frequency over time to find noise events (when it starts, how long it lasts). Tonal Teams averages the whole recording into one spectrum and asks which frequencies stick out, with no time dimension. Use Tonal Teams for a steady recording (a device running, a fan, an idle-noise capture); use Tonal Noise when the tone comes and goes. (Hover either menu item to see the same distinction in the status bar.)

Quick start:

  1. Load the recording. To test one channel, select it in the Channel: combo and leave nothing checked in Loaded Files. To test several channels at once (from one or several files), check their boxes in Loaded Files instead — each checked channel is tested separately with the same settings.
  2. If you only want part of the recording, set it first with Select Time Range...; Tonal Teams analyses only that part.
  3. Open Tools > Tonal Teams.... The defaults (threshold 6 dB, 100 Hz–16 kHz, 1 s lead trim) are a reasonable starting point. Click OK.
  4. Read each panel's title for PASS/FAIL, and the red Top fails: line under a failing panel for the worst frequencies.

Settings: every value is remembered in settings.ini ([TONAL_TEAMS]) when you click OK, and reused next time and by Export Report. The FFT size is not set here: it is the FFT Size in the main Settings... dialog.

SettingDefaultWhat it does
Threshold6 dBHow far the curve may rise above the baseline before that frequency counts as a failure. Lower = stricter (more fails), higher = more tolerant. A point fails only when it is more than this many dB above the baseline.
Gain Offset51 dBA fixed number of dB added to the signal before analysis, so the plotted levels land in a convenient range (for example close to the SPL your rig produces). It shifts the curve and the baseline by exactly the same amount, so it never changes PASS/FAIL — only the numbers on the level axis and in the CSV. Because of this offset the level axis reads “dBFS + Gain Offset”, not plain dBFS.
Lead Trim1 sSeconds cut from the start before analysis, to skip the click or ramp-up at the beginning of a recording. If the recording is shorter than this, nothing is trimmed. Applied in addition to any Select Time Range....
A-WeightingoffApplies an A-weighting filter (0 dB at 1 kHz) before the spectrum is computed, so the curve reflects how loud each frequency sounds to the ear. A smooth filter tilts the curve and the baseline together, so it has little effect on which narrow spikes fail; it mainly changes the shape and levels you see. This filter belongs to this tool and is not shared with other tools.
WindowHannWindow applied to each FFT frame. Hann keeps a tone's energy in a few neighbouring bins and is the right choice almost always; Rectangular gives the sharpest bins but lets a strong tone leak across the spectrum, which can lift the baseline around it.

Baseline Smoothing (bands/oct)3Width of the averaging window that makes the baseline: at each frequency the baseline is the average level over a window 1/N octave wide centred there (1/3 octave by default). This decides what counts as “narrow”: a spike much narrower than the window stands out above the baseline and can fail; a bump as wide as the window or wider is absorbed into the baseline and does not. A smaller number (wider window, e.g. 1) also catches broader resonances; a larger number (narrower window, e.g. 6) makes the baseline follow the curve more closely, so only very sharp tones fail.
Overlap50 %Overlap between consecutive FFT frames when averaging over time. Higher overlap uses the recording more evenly and gives a slightly smoother curve, at the cost of compute time.
Export Bins/Oct96Points per octave in the CSV export. The curve and baseline are interpolated onto this grid for the CSV, and a row is marked FAIL when a red marker falls on it. It does not affect the verdict or Top fails, which use the plotted points.
Top Fails Min Spacing100 HzThe smallest distance allowed between two frequencies in the Top fails list. One tone usually crosses the threshold on several neighbouring points, so without a spacing the three entries can all describe the same peak (for example 2001Hz, 1987Hz, …). With a spacing, points closer than this to an entry already listed are skipped, so the list names separate problems. Raise it if the list still repeats one peak, especially at high frequencies where a peak is many Hz wide; 0 lists the three largest points regardless of spacing. It only affects the list, never PASS/FAIL.

How it's computed:

  1. Cut the Lead Trim from the start, apply Gain Offset and, if enabled, the A-weighting filter.
  2. Compute one time-averaged spectrum for the whole remaining signal: FFT frames of the main FFT Size with the chosen Window and Overlap; the power of each frequency bin is averaged over all frames, so a steady tone keeps its true level and random noise settles to its average.
  3. Regroup that spectrum into 1/N-octave bands (High-Res Fraction) between Judge Fmin and Fmax. This is the cyan Signal curve.
  4. Smooth the Signal curve over the Baseline Smoothing window to get the orange Baseline: the channel's general shape with narrow spikes averaged away.
  5. The threshold guide line is the baseline plus Threshold. Every plotted point above it gets a red marker.
  6. The verdict uses exactly those plotted points: if at least one red marker lies in the judge range, the channel is FAIL, and the number of red markers is the fail count. What you see on the chart is what is judged. The points with the largest excess, at least Top Fails Min Spacing apart, are listed as Top fails (up to three, largest first): 1000.7Hz(+40.8dB) means that at 1000.7 Hz the curve is 40.8 dB above its baseline.

Since version 1.5.1 the verdict is judged on the plotted curve. Earlier versions (and the original Python tool) judged on the coarser Export Bins/Oct grid, where a narrow tone falling between two grid points could be interpolated away: it showed red markers but was missing from Top fails and could even leave the channel PASS. Results can therefore show more failures than before; every failure the old method found is still found.

Reading the result: each tested channel gets its own panel, titled with the channel's name and its verdict:

  • Signal (cyan) — the measured spectrum.
  • Baseline (thin orange) — the smoothed shape the signal is compared with.
  • Threshold (thicker orange) — baseline + threshold; anything above this line fails.
  • Red markers — the points above the threshold line.

Under a failing panel, the red Top fails: line names the worst three frequencies and their excess over the baseline. A single sharp failure usually means one discrete tone (a whine, an electrical frequency, a resonance); several failures at regular spacing (for example 100, 200, 300 Hz…) usually point to one source with harmonics.

Looking closer: every chart is interactive. Rest the mouse on a curve or a red marker to read its exact frequency and level (the label names the line: Signal, Baseline, Threshold or Fail). Drag a box with the left button to zoom into that area, turn the mouse wheel to zoom in/out around the cursor, hold the right button and drag to move the view, and right-click (without dragging) to return to the full view. The controls under the charts:

  • Overlay all channels (two or more channels) — replaces the stacked panels with one chart that draws every channel's Signal curve in its own colour, to compare channels or units directly. The legend shows each channel's name with its verdict, and failing points are marked with dots in the channel's colour; baseline and threshold lines are shown only in the separate panels. Uncheck it to go back.
  • Log frequency axis — switches every chart between a linear (default) and a logarithmic frequency axis; logarithmic gives the low frequencies more room. Switching resets the zoom.
  • Reset Zoom — returns every chart to its full view at once if you got lost while zooming or moving.
  • Save CSV... — see CSV export below.

The mouse wheel zooms while the pointer is over a chart, so scroll the list of panels with the scroll bar or with the pointer between charts. Export Report always uses the separate panels, never the overlay.

Tuning and troubleshooting:

  • Everything fails, or there are many scattered red markers. The threshold may be too strict for this kind of recording, or the noise floor is rough because there are few frames to average. Try a longer recording, a higher Threshold, or a higher Overlap.
  • A clearly audible tone passes. It may be outside the judge range, or wider than the baseline window so the baseline rises with it — lower Baseline Smoothing (e.g. 1–2 bands/oct) so the baseline is averaged over a wider window.
  • The curve looks like a staircase at low frequencies. There the 1/192-octave bands are narrower than one FFT bin, so several bands repeat the same bin value. Increase FFT Size in the main Settings... (frequency resolution = sample rate ÷ FFT size, e.g. 48 kHz ÷ 65536 ≈ 0.73 Hz), or lower the High-Res Fraction.
  • A failure right at the edge of the range. Near Judge Fmin and Fmax the baseline window is cut off on one side, so the baseline is less reliable there. Set the judge range slightly wider than the band you care about.
  • Comparing units fairly. Use the same settings and the same time range for every file (Select Time Range... with Apply this range to all loaded files), then use the overlay view.

CSV export: Save CSV... writes one file covering every channel in the window. Three header lines (export type, time, number of curves) are followed by a table with one row per point on the Export Bins/Oct grid (Frequency_Hz) and, for each channel, two columns: <name>_dBFS (the Signal level at that frequency, including Gain Offset) and <name>_Result (PASS, FAIL, or N/A where the point is outside the judge range or has no valid baseline). Baseline and excess values are not exported.

Waveform Statistics

A per-channel level report in the style of Adobe Audition's Amplitude Statistics panel, plus a switchable RMS-vs-time / frequency-response chart. It answers: how loud is this recording, how big are its peaks, is there a DC offset, and what does that come to in dB SPL and dBA for a calibrated microphone? It opens one dialog with one table column per channel.

What it analyses. If any channels are checked in Loaded Files (any combination across any loaded files, sample rates may differ), one column per checked channel is shown; otherwise it covers the current file, one column per channel. If you set a time range with Select Time Range..., only that range is analysed. Columns are computed in parallel, so many channels take roughly as long as the slowest one.

Reading the table. All levels are relative to full scale, with a full-scale square wave = 0 dB (so a full-scale sine reads about −3 dB RMS). A silent channel reads -inf. N/A means the value cannot be computed (see the notes below).

Total RMS Power (dB)dBFSOne RMS over the whole channel (DC removed), no windowing. For a steady signal it is close to Avg RMS; for a signal with loud bursts and long quiet gaps the two differ.
dB SPL (broadband)dB SPLAvg RMS Power + Cal_Offset: the average sound pressure level at the microphone, all frequencies counted equally. Needs correct calibration values (below).
dBAdBAThe average level after A-weighting (the IEC 61672 curve that discounts low and very high frequencies the way human hearing does), plus Cal_Offset. This is the number comparable to a sound level meter's A-weighted equivalent level. The signal is DC-removed, A-weighted first, then run through the same window / linear-average / dB steps as Avg RMS.
Max RMS dBAdBAThe highest A-weighted window RMS (plus Cal_Offset): the loudest moment as the ear would rate it, similar in spirit to a meter's maximum-level reading. The window length sets how short a burst it can resolve.
Peak dBAdBAThe largest single A-weighted sample (plus Cal_Offset). Catches short clicks and pops that Max RMS dBA averages away: a brief loud click can give a high Peak dBA but a much lower Max RMS dBA. For a pure sine, Peak is about 3 dB above Max RMS.

Calibration (dB SPL, dBA, Max RMS dBA, Peak dBA). The first eight rows are in dB relative to full scale and need no calibration. The last four convert to real sound pressure by adding a constant Cal_Offset:

Cal_Offset = Reference SPL − (Mic Sensitivity + Convention offset)

  • Mic Sensitivity (dBFS) — the microphone's output level, in dBFS, at the reference sound level (from its datasheet, or from the Calibrate... function of the real-time level meter). Default -26.
  • Reference SPL (dB) — the sound level that sensitivity figure was specified at. Default 94 (a standard acoustic calibrator).
  • Convention offset (dB) — reconciles the two level conventions: this table puts a full-scale square at 0 dB while microphone datasheets quote sensitivity against a full-scale sine. Default -3.01; leave it unless you know your reference differs.

With the defaults Cal_Offset is 123.01 dB. If you set a Gain... on a file in Loaded Files, its column's last four rows subtract that gain, so they still show the real level at the microphone (the first eight rows include the gain, because they describe the signal as analysed). These three boxes recalculate the last four rows instantly as you type, and the resulting Cal_Offset is displayed under them. They are session-only and return to the defaults next time.

RMS window and A-weight skip. Two settings control how the RMS rows are computed. After changing either, click Recalculate (they are not applied while typing, because recalculating re-runs the A-weighting on every channel).

  • RMS window (default 50 ms) — length of the sliding window. A shorter window follows fast level changes and gives higher Max / lower Min values; a longer one smooths them. It affects Min / Max / Avg RMS Power, dBA, Max RMS dBA, and the RMS curve in the chart.
  • A-weight skip first (default 250 ms) — how much of the start of the A-weighted signal to ignore. The A-weighting filter starts from silence, so its first moments contain a start-up transient that is not part of the real signal; skipping avoids it polluting the average and peak. It affects dBA, Max RMS dBA and Peak dBA. Set it to 0 to ignore nothing (for example, when a loud event happens at the very start of the file). If the skip is longer than the clip, the whole clip is used.

The current values are shown in the line at the top of the dialog and are included when you copy the table. Both are remembered in settings.ini's [WAVEFORM_STATISTICS] section (rms_window_ms, a_weight_skip_ms) and reused next time, including by File > Export Report.

The chart. Use the View dropdown to switch:

  • RMS vs Time — the sliding-window RMS curve of every column, so you can see when the loud and quiet parts are. The dB amplitude axis checkbox switches the vertical axis between dB and linear amplitude.
  • Response vs Frequency — the magnitude spectrum of each whole channel from 20 Hz up to half the sample rate. The checkbox changes to Log frequency axis and switches the horizontal axis between logarithmic and linear.

Click a table column to emphasise that channel's curve and fade the others; drag a rectangle or scroll the wheel to zoom, drag with the right button to move the view, right-click or Fit to Data to reset, hover for exact values. The chart is not affected by the calibration boxes. Because RMS is computed on the plain (not A-weighted) signal, the chart's curve matches the Min/Max/Avg RMS rows, not the dBA rows.

Copy to Clipboard copies the whole table (with the header line, calibration values and one tab-separated column per channel) for pasting into a spreadsheet.

Why a value shows N/A: the RMS and dBA-family rows need at least one full window of audio, so a channel shorter than the RMS window shows N/A for them (the sample, peak, DC and Total RMS rows still work). Shorten the window or analyse a longer range. A channel with no audio at all is N/A in every row.

Design

Datasheet and simulation calculators for speaker/microphone hardware selection — distinct from Tools' measurement features in that none of these need a loaded audio file. Each opens as a single reused window; reopening its menu item brings the same window forward rather than stacking a new one.

Mems Mic Design...

Compares two MEMS microphone datasheets side by side — Sensitivity, SNR, AOP, LFRO, Peak — against an SPL/distance slider. Can open a linked Sealing Analyzer for port/cavity sealing cross-section analysis.

Speaker Design...

A loudspeaker-array datasheet analyzer with a beam-map chart showing how the array's directivity changes with its control parameters.

Speaker Test SOP...

A production-line test-development reference: pick an architecture and a loudness level, and it shows the expected SPL chart, a pass/fail coupling-metrics grid (THD/PRB against limits), an architecture-specific coupling-analysis panel, and the matching SOP text.

Speaker Selection Sim...

A driver-selection simulator — pick a driver type and tune Target SPL, Install Size, Enclosure Volume, and DSP Bass Boost sliders and a Quality setting to see the resulting frequency response and physical excursion.

Acoustic Design Guide...

A side-volume calibration guide (English/Traditional Chinese toggle) — four sliders and a DSP-calibration toggle drive a stereo frequency-response chart and an imaging-shift gauge, with commentary alongside.

Acoustic Methodology Manual...

A two-step reference covering individual near-field measurement versus array far-field summation — four sliders drive a frequency-response chart and the same imaging-shift gauge, alongside the full engineering-manual text.
